# weather-normals

Open-Meteo の気象データを使って、今日の気温が平年と比べてどうか、
過去の記録の中で何位に相当するかを表示するツールです。

## これは何をするツールか

指定した地点(省略時はさいたま市付近、緯度35.86 / 経度139.65)について、

1. 過去(ERA5アーカイブ)の同じ月日の記録から「平年値」を2種類計算する
2. 今日の気温(Forecast API)を、ERA5基準に補正した上で平年値と比較する
3. 平年より暑いか寒いかに応じて、最高気温 or 最低気温で過去の記録に対する順位を出す
4. 加えて、この地点の8月平均気温が過去70年でどう推移してきたかを表示する

を1本のスクリプト `fetch_era5.py` で行います。

## データソースとその特性

### ERA5アーカイブ(過去データ)
- `https://archive-api.open-meteo.com/v1/archive`
- ECMWFの再解析データ。0.25度グリッド(南北約28km、東西約22km、
  北緯36度付近の場合)で、指定座標に最も近い格子点の値が返る。
  経度方向の実距離は緯度によって変わり、日本付近では東西に潰れた
  長方形になる。**気象台のピンポイント観測値とは別物**
- 1940年から取得できるが、直近数日分は反映が遅れる(このスクリプトでは
  `end_date` を今日より少し前に固定している)
- 30年〜85年分をまとめて1リクエストで取得する(日ごとに叩かない)。
  Open-Meteoへの負荷を減らし、レート制限も避けるため

### Forecast API(今日の値)
- `https://api.open-meteo.com/v1/forecast`
- ERA5とは異なる数値予報モデルを使っており、グリッドの切り方も違うため、
  同じ座標を指定しても微妙に異なる格子点の値が返る
- ERA5にはまだ存在しない「今日」の値を得るために使う。ERA5とは
  データソースが違うため、そのままでは平年値と単純比較できない

### バイアス補正
ERA5とForecast APIは同じ日でも値がズレることがあるため、直近7日間で
両方のデータがある日を比較し、平均差分(バイアス)を計算して今日の値
から差し引く仕組みを入れている。

当初は単日(1日分)の比較で約1℃前後の系統的なズレがあると判断していたが、
これは外れ値1日だけを見た誤った結論だった。実際に7日分で検証したところ、
6日は±0.5℃以内に収まっており符号(プラス/マイナス)もバラバラで、
平均すると-0.1℃とほぼズレなしという結果になった。つまり「系統的な
バイアス」ではなく、日々のノイズだったということになる。

このため現時点で検出されているバイアスはほぼゼロだが、補正の仕組み
自体は残してある。将来的にモデルの更新などで系統的なズレが発生した
場合にも自動的に検出・補正されるようにするためで、今ズレがないことを
確認したからといって仕組みを外す理由にはならない。

なお、7日という日数で単純平均しているのは「バイアスがあるかどうかも
分からない段階で補正方法(重み付けなど)を精緻化しても、ノイズに合わせる
だけになる」という考えから。上記の検証結果はまさにその通りで、
精緻化しなかったからこそ「実はノイズだった」と判別できた。

## 平年値A・Bについて

同じ「平年値」でも、期間の取り方で計算方法を2種類出している。

- **平年値A**: 1991-2020年の固定30年間(気象庁が公式に使っている
  基準期間と同じ)
- **平年値B**: 直近30年のローリング(スクリプト実行時点から遡って30年)

Aは毎年同じ基準で比較したいとき、Bは「直近の気候」により近い基準で
比較したいときに向いている。**AとBの差そのものが、この地点の温暖化の
目安になる**ため、どちらか一方に絞らず両方表示している。

「平年との差」やランキングの暑さ/寒さ判定には、最新の気候をより
反映するBを使っている。

## 気候セクション(10年ごとの8月平均気温)

8月27日単日のデータは年による振れ幅が大きく、長期トレンドを見るには
ノイズが大きすぎる。そのため8月全体の平均を10年区切りで集計し、
この地点の気候がどう変化してきたかを別枠で表示している。

実際にこのデータで確認したところ、1940年代〜2000年代はほぼ横ばい
(25.4〜26.0℃)で、2010年代以降に急上昇している(2010年代26.9℃、
2020年代28.4℃)。1940-1978年(衛星観測が本格化する前)が特別
高温側に偏っているような、データバイアスを疑う兆候はなかった。

なお直近の10年区切り(現在は2020年代)は年数が10年に満たないため、
表示に `※n年分` の注記を付けて母数が違うことを明示している。

## セットアップ

```bash
cd weather-normals
python3 -m venv .venv
source .venv/bin/activate
```

外部ライブラリは使用していない(標準ライブラリのみ)ため、
`pip install` は不要。

## 使い方

```bash
python fetch_era5.py
```

初回実行時はOpen-MeteoのAPIから直接データを取得し、`cache/` ディレクトリに
JSONをそのまま保存する。2回目以降は同じ地点・期間のリクエストであれば
キャッシュを読むだけで完結し、ネットワークアクセスは発生しない。

地点や対象日を変えたい場合は、以下のオプションを指定する(すべて省略可能)。

```bash
python fetch_era5.py --lat 43.06 --lon 141.35 --date 2026-01-15
```

| オプション | 説明 | 省略時 |
|---|---|---|
| `--lat` | 緯度 | `35.86`(さいたま市付近) |
| `--lon` | 経度 | `139.65`(さいたま市付近) |
| `--date` | 対象日(`YYYY-MM-DD` 形式) | 今日 |
| `--no-cache` | キャッシュを無視して再取得する | 指定なし(キャッシュを使う) |

`--date` に `YYYY-MM-DD` 以外の形式を渡すと、その場でエラーメッセージを
出して終了する(例: `2026/08/27` のようなスラッシュ区切りは弾かれる)。

キャッシュを無視して強制的に再取得したい場合:

```bash
python fetch_era5.py --no-cache
```

キャッシュは速度のためではなく、**Open-Meteoのレート制限(429)を
避けるため**に導入している。ファイル名に地点と期間(緯度・経度・
開始日・終了日)を含めているので、期間を変える(例: 対象日を進める)と
自動的に別ファイルとして扱われ、古いキャッシュは使われなくなる。
有効期限を管理する仕組みは意図的に入れていない(過去データは
基本的に変化しないため、そのままにしておいても問題にならない)。
不要になった古いキャッシュは `cache/` ごと手動で削除すればよい。

## 既知の制約

- **ERA5は0.25度グリッドの値であり、気象台のピンポイント観測値とは
  異なる。** 指定した緯度経度に最も近い格子点の値が返るだけで、
  その地点そのものを観測しているわけではない
- **今日の値はForecast API由来であり、過去の記録(ERA5)とはデータ
  ソースが異なる。** バイアス補正はしているが、完全に同一の基準に
  揃っているわけではない。そのためランキング表示では、ERA5のみの
  過去分布と、そこに今ソースの違う今日の値を当てはめた場合の順位を
  明確に分けて表示している
- **Open-Meteoにはレート制限があり、過去に実際に429エラーが発生した
  ことを確認している。** これがキャッシュを導入した理由であり、
  速度目的ではない
- **平年値は生の日別平均をそのまま使っており、気象庁が公式に行っている
  ような平滑化(前後の日を含めた移動平均など)は行っていない。** その分
  簡単に計算できるが、単日の値は年々のばらつきの影響を受けやすい
- **地点によっては、1940年代前後のERA5データに不自然な高温の
  かたまりが見つかっている。** 実際に確認した事実:
  - 札幌(43.06, 141.35)では1943-1951年の8年間が、前後の年より
    約2℃高い8月平均気温を示す
  - 同じ期間をさいたま(35.86, 139.65)で確認したが、同様のかたまりは
    見られなかった。したがって日本全体に共通する問題ではない
  - 札幌では通年平均でも約+0.9℃高いが、1月平均は年によるばらつきが
    大きく、一貫した傾向は見られなかった
  - このため、**1940年以降の全期間ランキングは、地点によっては
    古い年代のデータ品質に影響される可能性がある**

  (以下は推測であり、原因を特定できたわけではない)
  夏に強く冬に不安定という季節性から、当時の海面水温データの不足など、
  観測データの疎密がERA5の同化過程に影響した可能性が考えられるが、
  原因は特定できていない。

  **利用者への注意:**
  - 1940年以降のランキングより、1979年以降(衛星観測時代)の
    ランキングのほうが信頼できる場合がある
  - 新しい地点でこのツールを使うときは、まず「10年ごとの気温推移」の
    表示を見て、古い年代に不自然な跳ねがないか確認することを推奨する
